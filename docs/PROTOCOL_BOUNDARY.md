# Offline boundary

Authority issues signed GCL1 entitlement and GCV1 revocation documents against GCR1 installation requests. GatewayCore customer runtime remains independent, requiring only pinned public verification keys. The copied SDK is pinned to source commit 5a0d5f1470a5dd8b853113b1e96b48348cb52c38; synchronization must be reviewed and protocol interoperability tested on both repositories before release. No customer deployment calls this repository or portal. Production key storage is external to Git and separated from the web portal. No release authorization.

The PostgreSQL acceptance workflow now separately checks out customer source 58f55b98b253c023d0ec824f17e001c9677c1929, builds the CustomerInterop executable against that checkout, and exchanges actual signed GCR1/GCL1/GCV1 files with the database-backed authority. The customer executable is invoked in independent processes to provision, renew, reject rollback, revoke and inspect persisted state. The snapshot equality check remains separate. Only ephemeral test keys and synthetic records are used. Full actual GatewayCore gateway runtime interoperability remains a separate customer-side no-egress acceptance suite.
